- **How vectors are compared and labeled as "most-relevant" and "least-relevant"**
	  1. **The Massive Math Plot:** Text documents are processed by a specialized AI encoder. This encoder maps human concepts into long strings of numbers (vectors) and plots them onto a massive, high-dimensional mathematical grid.
	     
	2. **Plotting the Query:** When a user asks a question, that question is converted into a query vector using the exact same encoder. This query vector is then plotted onto the same mathematical grid.
	   
	3. **The Angle Math:** Instead of using linear regression, the system uses **linear algebra**—specifically an algorithm called **Cosine Similarity**. It measures the geometric angle between the query vector and all the data vectors.
	   
	4. **The 1.0 Score Rule:** The closer the mathematical value is to **1.0**, the tighter the angle between the vectors, meaning they point in almost the same direction. The closer it is to 1.0, the more similar the data is to your question.

## Text Chunking
- **what is text chunking?**: 
	  breaking large strings into chunks 

	- how chunking works in details:
	  
	- why we need chunking: 
		since the context window of LLM models are finite (see below), chunking helps splitting large texts into smaller ones and only picking what's relevant.
		- context windows sizes:  
			- Gemini 3: 1 million
			- Claude sonnet: 1 million
			- GPT5-1: 400k

- chunking is not a permanent solution then?:
	  Chunking doesn't make the cost/latency problem disappear — it just mitigates it, permanently, every time you use it. That's because feeding the LLM information, even only relevant chunks, still costs something, and that cost still scales quadratically with the number of tokens fed in.

- other benefits of chunking?:
	  If a large chunk covers multiple topics, the embedding vector of the large chunk reflects each of the topics weakly, If we break the large chunk into smaller chunks, each smaller chunk will focus on one topic and, thus, its embedding will better represent that topic. basically , the more smaller chunks the more relevant and efficient for context window and accurate responses. 

- chunking strategies:
	- fixed-size: is the basic chunking method ever , not good becuase it may cut context in half , leading to miss the context, (example if a page was talking about somehing and chunks are configured to cut in half pages , this would split the page in half and lose the meaning of that page)
	  
	- content aware chunking: this would keep an eye on sentence boundreis. has multiple vartiants and the main idea of these variants is to use the file structure such as seperators and page splits or headings like those in md files (# ## ###)
	  
	- semantic chunking: is the most advanced variant between them that keeps an eye mostly on context or "meaning" 

## Embedding

### intro 
An embedding maps a piece of text (a chunk, or a user's query) into a vector of floating-point numbers. Semantically similar text ends up with vectors that are numerically close together — even if the words are completely different on the surface.

> **Embedding** — a fixed-length list of numbers representing the meaning of a piece of text, generated by a neural network.

> **Dense retriever** — a retrieval system built on embeddings (as opposed to keyword-based "sparse" retrieval like plain full-text search).

**Why this matters:** if a user searches "Uncle Sam" but your document says "US Government," plain keyword search finds _nothing_. Embeddings catch this because both phrases land near each other in vector space — meaning wins over surface spelling.

The reverse also matters: "cat" and "hat" look similar as strings but mean nothing alike — a good embedding model keeps their vectors far apart despite the surface similarity.

#### search part
- **what are the properties of a vector?:**
	  - direction: it's which way it points (this encodes the "meaning")
	  - magnitude: how long the vector is (this can vary for reasons that have nothing to do with meaning — e.g. longer sentences sometimes produce longer vectors, purely as a side effect of the model's math)

- **why magnitude causes a problem?**:
	  if you compare two vectros using raw dot product alone, a vector with a bigger magnitude would score get more similarity score just because the word is longer. 
	  - **fix**?: **normalization**: dividing every vector by it's own magnitude forcing every vector to have the length exactly of 1  

- **what is ANN and what it fixes?:** 
	  instead of iterating one by one which is O(n) and that would be slow on billionic databases, this algorithm simply catches the "approximate nearest neighbor" it and catches the closest one enough and not the exact one (fair enough) 

- **most famous ANN algorithm?:**
	  HNSW (Hierarchical Navigable Small World) which makes a multi layer strucutre that each vector is conncted to nearby vectors with the same layer, upper layers contains small number vectors that represent a view on the dataset (it's like a big family with alot of family members and grandsons)
